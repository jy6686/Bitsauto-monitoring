Production observations

The three documented limitations also seem appropriate to carry forward as known items rather than certification blockers:

Configurable scheduler fallback
Reasonable enhancement for production deployments where "today only" versus "latest available DMR" should be a configurable policy.
Queued response during advisory lock
Acceptable if intentional, but worth documenting so operators understand the API behavior.
safeQuery swallowing schema errors
This is the one I'd keep an eye on. Silent failures are convenient for dashboards, but they can delay detection of schema regressions. If you continue using this pattern, consider logging enough diagnostic information internally to make future issues easier to diagnose.
