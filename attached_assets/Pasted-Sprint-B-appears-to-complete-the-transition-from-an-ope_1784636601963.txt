One refinement I'd consider (not required for Sprint B)

Right now, /api/commercial/intelligence is an aggregation endpoint.

As it grows, consider internally structuring it into domain services while keeping the external API unchanged.

For example:

Commercial Intelligence Service
        ├── Traffic Analyzer
        ├── Quality Analyzer
        ├── Risk Analyzer
        └── Commercial Analyzer

The client would still call only:

GET /api/commercial/intelligence

This keeps the API stable while allowing the implementation to evolve.
