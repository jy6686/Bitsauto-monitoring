What should happen next

I would treat the four runtime gates as the only blocking work before F3.

Gate 1 — Scheduler Cadence

Evidence should demonstrate:

Initial delay behaves as configured.
30-minute cadence is maintained.
Advisory lock prevents overlapping executions.
Scheduler resumes correctly after a service restart.
Gate 2 — Snapshot Correctness Trace

This is the most important gate because it validates the canonical financial data.

Evidence should include a complete lineage:

CDR/DMR
    ↓
financial_snapshot
    ↓
Finance Cockpit

showing identical values at each stage for the sampled records.

Gate 3 — Failure Injection & Recovery

This validates transactional integrity.

The expected evidence is:

No partial snapshot rows remain after rollback.
One failed materialization_runs record exists with appropriate failure status.
Subsequent scheduled execution succeeds without manual intervention.
Gate 4 — Performance Baseline

Rather than only recording raw execution time, I'd preserve enough information to compare future releases.

Useful baseline fields include:

Snapshot row count
Runtime
Rows/second
Clients processed
Vendors processed
Peak memory (if available)
Database execution time (if measured)
Materialization version

Those metrics make future regressions much easier to identify.
