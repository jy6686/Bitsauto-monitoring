https://app.example.com/noc

or to the corresponding page inside their portal if one exists.

Likewise, a Finance-only user:

Access Scope: PORTAL_ONLY
Default Portal: finance

logs in to:

/finance

If they remove /finance from the URL:

/

they are immediately redirected back to:

/finance

They never see the main platform.

can navigate freely:

/
/clients

/noc

Multi-Portal users

Access Scope: MULTI_PORTAL
Assigned Portals:
- noc
- finance
- commercial

they can access:

/noc
/finance
/commercial

but not:

/admin

unless Admin is one of their assigned portals or they have full-platform access.

This should be enforced centrally

The enforcement should not rely on every page checking permissions.

Instead, use a centralized guard:

Request
    ↓
Authentication
    ↓
Authorization
    ↓
Route Check

The route check should evaluate:

Is the user authenticated?
What is their accessScope?
Is this route part of the main platform or a portal?
Is the requested portal one of the user's assigned portals?

If the answer is no, redirect to the user's landing route.

I'd make the rule more general:

Any request for a route outside the user's authorized scope is intercepted before rendering. The user is redirected to their landing route (or shown an Access Denied page if appropriate).

Typing /admin
Deep-linking into another portal
Bookmarking unauthorized pages
