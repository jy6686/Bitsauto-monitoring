# BUG-004 — Destination "Apply" / premature destination load

- **Objective:** destinations/rates load only after a destination (or product) is
  selected; "Apply" stays disabled until then.
- **Scope:** `client/src/pages/destination-catalog.tsx` (queries + Apply controls).
- **Acceptance criteria (verify on current deploy):**
  - On page load, no API call fetches all destinations/rates before a selection.
  - "Apply" is disabled until a destination/product is chosen.
- **Dependencies:** current code must be deployed (rule out deploy lag / stale cache).
- **Status:** **OPEN — needs runtime reproduction.** Code trace shows the "Apply
  rates to product" button is gated and by-destination panels take a `destId` prop;
  no ungated all-destinations query found on mount (3.8k-line file — not exhaustive).
- **Owner:** Commercial.
- **Verification:** ☐ runtime — Network tab on page load: which API fires before
  any selection, which query has `enabled:true`, which component renders first.
- **Related Bug(s):** none.

- **Related VR:** none.
